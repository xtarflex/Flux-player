## 2025-03-01 - Fix Command Injection Risk in Uninstaller Registry Parsing
**Vulnerability:** The application was reading the `UninstallString` directly from the Windows Registry and passing it unparsed to `std::process::Command::new()`. This could lead to unsafe execution if the path contained spaces and was unquoted, or arbitrary command execution if the registry string was manipulated by another process to include extra commands or point to malicious executables.
**Learning:** Windows Registry command strings often contain paths with spaces and arguments (e.g. `C:\Program Files\uninstall.exe /S`). Standard parsers like `shlex` strip backslashes assuming POSIX environments, which destroys Windows file paths. `CommandLineToArgvW` or a careful custom parser is necessary.
**Prevention:** Implement a Windows-safe parser that handles quotes and backslashes properly to separate the executable path from arguments, then strictly validate the extracted executable to ensure it is absolute, exists, and has a safe extension (`.exe`, `.msi`, `.bat`, `.cmd`).
